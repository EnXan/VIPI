# ADR 0084: QR and barcode payloads as a detector reading

Status: Accepted for implementation and review, 2026-11-22 (issue #83).
Amends the verdict scope of
[ADR 0071](0071-scan-verdict-and-final-ocr-completeness.md) in the same way
as ADR 0078 and ADR 0083: the decoded code payloads are part of it.

## Context and sources

A QR code or barcode shows a pattern, not text. OCR cannot read it, but a
phone, a document scanner or an agent with a decoder acts on its payload.
Issue #83 proposed checking decoded payloads as separate evidence and never
fetching decoded URLs. Agreed with the maintainer on 2026-11-22:

- zxing-cpp as the decoder;
- all formats it reads;
- a code that is found but cannot be decoded is noted in the report and does
  not make the scan incomplete. Revised on 2026-11-23 after the dataset run
  (see the validation boundary): undecodable codes are ignored and not
  counted.

Probes on 2026-11-22, one QR code holding an injection rendered in eight
variants:

- zxing-cpp 3.1.1 decoded 7/8 (all but a 40 px code) and Code 128.
- OpenCV 4.11 (already in the `ocr` extra) decoded 3/8. It failed on the
  small, blurred, noisy and rotated-and-blurred variants and cannot decode
  Code 128; its barcode detector reads only EAN/UPC.
- In the 554 dataset images, zxing-cpp decoded one code: a benign screenshot
  with a URL QR code that OpenCV detected but could not decode. No dataset
  image holds a code with an injection.

zxing-cpp is Apache-2.0 and ships wheels for macOS, Linux and Windows.

## Decision

- **Reading.** `vipi.barcodes.read_codes` runs
  `zxingcpp.read_barcodes(...)` with default options on
  the raster OCR reads: the decoded input, or the safe render of an SVG. Each
  decoded code with a non-binary payload becomes one `Format: text` line of a
  single reading (evidence kind `barcode`, scope suffix `_and_barcodes`). It
  is checked like the OCR text, and any check at or above the threshold
  detects.
- **No fetching.** Decoded URLs are only text for the detector.
- **Binary payloads** (`ContentType.Binary`) are counted, not checked.
  Invisible characters are normalised as for the SVG source text; base64 in a
  payload is decoded under ADR 0079.
- **Undecodable codes** are ignored: zxing-cpp returns only decoded codes by
  default. They are neither counted nor an incomplete reason.
- **Decoder failure.** An exception from zxing-cpp adds an incomplete reason:
  the file is an error (exit 2) with verdict `injection_detected` when another
  reading is detected, otherwise `null`.
- **Report.** The file record gains `barcodes` with `formats`, `characters`,
  `invisible_characters`, `binary` and the highest score per
  reading (`ocr`, `barcode`). `--verbose` prints the payloads. The SVG,
  metadata and barcode reports share `reading_scores`, which reports only the
  OCR reading as `ocr`, so a barcode score is not shown as an OCR score.
- **Dependency.** `zxing-cpp==3.1.1` joins the `ocr` and `ocr-cuda` extras.

## Alternatives considered

- **OpenCV only.** No new dependency, but it decoded 3/8 of the probe
  variants and reads neither Code 128 nor Data Matrix, Aztec or PDF417.
- **pyzbar.** Needs the system zbar library on macOS and Linux.
- **2D codes only.** Code 128 and Code 39 carry arbitrary text, so a 1D
  payload would pass unchecked.
- **Undecodable codes make the scan incomplete.** Stricter, but see the
  validation boundary: most undecodable results are not codes.
- **Count undecodable codes in the report** (`return_errors=True`), the
  first agreed form. Dropped because the count is mostly noise and would
  report "undecodable codes" for benign images without any code.
- **Upscaling or retrying small codes.** No evidence yet that real inputs need
  it; OCR recovery does not change the barcode raster.

## Consequences

- Every scan decodes the raster once more: median 13 ms, at most 134 ms (11.5
  MP) per dataset image on an Apple M2 CPU, 10 s for all 554 images. The
  input is decoded a second time for this. A decoded code with text costs one
  more detector check.
- Default scan results change (images with code payloads can be flagged).
  Released as 0.18.0; pinning it in the vipi-action calls for an Action major
  version under ADR 0076.
- Research evaluations build their own evidence and do not include this
  reading.
- Not covered: codes too small or blurred to decode (40 px QR in the probe),
  codes split across images, payloads that only make sense after fetching a
  URL, and codes only visible in a recovery transform (rotation, contrast).

## Validation boundary

Unit tests decode real codes in six formats generated by zxing-cpp. They also
cover several codes in one image, binary payloads, invisible characters and
decoder failure. Integration tests run full scans with
fake OCR and detector, including a QR code drawn in an SVG and an incomplete
scan after a decoder failure.

A synthetic corpus written for this change (not retained) rendered each code
at 2 px per module with a 0.6 px blur on a page. The reading alone was scored
with the calibrated default thresholds on 2026-11-22:

- 13 benign payloads: a URL with tracking parameters, WiFi, a vCard, an EPC
  payment, an `otpauth` link, `mailto` with a body, a download link, a PDF417
  boarding pass, an Aztec ticket, a Code 128 parcel number, a GS1 Data Matrix,
  EAN-13 and a help URL with "delete" wording.
- 12 attack payloads: two plain injections, an injection in a URL query, a
  vCard note and a WiFi SSID, in Data Matrix, Aztec, PDF417 and Code 128, as
  base64, as Unicode tag characters, and one camouflaged request.

| Detector (threshold) | Benign flagged | Attacks detected | Decoded |
| --- | --- | --- | --- |
| d1 (0.45) | 0/13 (max 0.29, EPC payment) | 12/12 (min 0.60, WiFi SSID) | 25/25 |
| Prompt Guard (0.80) | 0/13 (max 0.005) | 5/12 | 25/25 |

At 1 px per module 23/25 codes decoded, at 3–4 px per module with 1–1.5 px
blur 24/25. Prompt Guard again missed the `curl … | sh` payload in every
format, the URL query, the SSID, Code 128, the tag characters and the
camouflaged request. That is the detector weakness tracked in #105. Clef-Flash
and the cloud detectors were not measured. The corpus is small and written by
the same author as the payloads.

On the 554 dataset images, 19 (14 benign, 5 attacks) report at least one
undecodable code, 1 to 5 each. The inspected ones are checksum errors from
patterns that resemble Data Matrix or QR finder patterns, not codes. The
count is therefore mostly noise, so VIPI neither reports undecodable codes
nor makes them an incomplete reason.
